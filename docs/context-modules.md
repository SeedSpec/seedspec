# Context modules

> Informative. Normative rules are in `protocol.md`.

A context module is supporting material with a direct Markdown
entrypoint. It can be a skill, an eval, a policy, a profile, or other
readable context.

`SPEC.md` is the destination. Modules are not a second spec.

## 0.4 shape

- Direct path from the package root
- Closed core `type` for grouping
- Optional format metadata for deeper interpretation
- Applicability may select by lifecycle stage, local capability, or local
  success criterion

No required headings. No bridge-Skill protocol. No preparation receipt
as package content.

## Authority

Visibility is not mutation, installation, or execution. Non-primary
module bodies are fixed inputs to ordinary authoring: inspect, do not
rewrite as a side effect of editing the spec.

Authors choose what to include. Do not fill modules for appearance.
